# Проверка перехода на Chromium 156

Изменения подготовлены в отдельной ветке `update/chromium-156` поверх Argon
`b3aef5609223745471dcd3c4cdf1aa2b9c7d62b3`. В историю ветки включён входящий
коммит Titanium `a3e4b86339a8db237d95d8e8e78248c8f6a1df68`.

готовые APK прежней версии не соответствуют новым входам.

## Изменения тестовых входов

- AndroidX AAR: SHA-256
  `a7fd8d404c9915bd69341bbd23319a7becf8f05a26f44fa7d8661c3caf2b76ff`.
- AndroidX source JAR: SHA-256
  `80e89a8eaf2bc9c0fd52a3818815e59de891ef413433d81484359e084268d965`.
- `TimePeriodUtils` M156 отличается от старой fixture только последней пустой
  строкой; обработчики инициализации, выбора и перехода пересверены с M156.
- Проверка DevTools теперь охватывает применение новой ветки патча к настоящим
  исходникам, дополнительно к существующим тестам границы версии.
- Интеграционные тесты получают файлы с официального Chromium Gitiles по полным
  commit SHA. Ограничение GitHub `429` не требует смены версии или отключения
  проверок. Временные ошибки повторяются до трёх попыток; отсутствующие файлы,
  некорректные ответы и исчерпание попыток остаются ошибками.
  Запросы выполняются последовательно с секундной паузой; `Retry-After`
  учитывается, а при `429` без этого заголовка выдерживается 30 секунд.

## Проверка CI до слияния

`validate.yml` сначала проверяет отпечаток общего prepared image. При совпадении
используется его immutable digest. При изменении входов собирается локальный
`argon-validation:local` из checkout этой ветки с использованием registry cache.
Образ загружается только в Docker runner; `push: false`, публикации в GHCR нет.
Проверка точных pins перед запуском production domain tests остаётся обязательной.

Это устраняет зависимость проверки Chromium 156 от предварительного обновления
общего `branch-main` image. Релизные workflows, разрешение публикации только из
`main`, ключи подписи и правила retention не меняются.

## Границы подтверждения

Локально выполнены preflight обеих архитектур, Python suite, интеграция патчей
с закреплённым Chromium, host playback flow и C++ constraints с новым BoringSSL.
Один Python-тест, требующий `/dev/fd`, пропущен ограниченной локальной средой;
GitHub runner запускает его в обычном Linux-окружении.

Проверки GURL/ICU/PSL и полного prepared checkout следует оценивать по GitHub
Actions этой ветки. Host-сценарии не подтверждают компиляцию Android JNI/Java,
установку APK, реальные TLS-соединения и поведение на устройстве. Перед релизом
нужны APK для обеих ABI и Android smoke tests, включая расширения, настройки
сертификатов, фоновое воспроизведение и оба окна очистки данных.
