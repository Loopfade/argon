`b3aef5609223745471dcd3c4cdf1aa2b9c7d62b3`. В историю ветки включён входящий

## Изменения тестовых входов

- AndroidX AAR: SHA-256
  `a7fd8d404c9915bd69341bbd23319a7becf8f05a26f44fa7d8661c3caf2b76ff`.
- AndroidX source JAR: SHA-256
  `80e89a8eaf2bc9c0fd52a3818815e59de891ef413433d81484359e084268d965`.
- `TimePeriodUtils` M156 отличается от старой fixture только последней пустой
  строкой; обработчики инициализации, выбора и перехода пересверены с M156.
- Проверка DevTools теперь охватывает применение новой ветки патча к настоящим
  исходникам, дополнительно к существующим тестам границы версии.
- Интеграционные тесты получают файлы с официального Chromium Gitiles по полным
  commit SHA. Ограничение GitHub `429` не требует смены версии или отключения
  проверок. Временные ошибки повторяются до трёх попыток; отсутствующие файлы,
  некорректные ответы и исчерпание попыток остаются ошибками.
  Запросы выполняются последовательно с секундной паузой; `Retry-After`
  учитывается, а при `429` без этого заголовка выдерживается 30 секунд.

## Проверка CI до слияния

`validate.yml` сначала проверяет отпечаток общего prepared image. При совпадении
используется его immutable digest. При изменении входов target
`domain-policy-tests` подготавливает checkout этой ветки и выполняет production
domain tests внутри BuildKit с использованием registry cache. `load: false` и
`push: false` оставляют результат в build cache без экспорта и повторного импорта
большого checkout в Docker daemon. Проверка точных pins остаётся обязательной.

Первый прогон подтвердил полную подготовку Chromium, C++ constraints и GN,
но импорт дополнительной копии образа завершился `no space left on device`.
Отдельный test target устраняет именно этот расход диска. Финальный production
stage по-прежнему наследуется от `prepared` и сохраняет пользователя `argon`.

Это устраняет зависимость проверки Chromium 156 от предварительного обновления
общего `branch-main` image. Релизные workflows, разрешение публикации только из
`main`, ключи подписи и правила retention не меняются.

## Результат повторной проверки

[Прогон 39821039858](https://github.com/Loopfade/argon/actions/runs/39821039858)
для кода `ed6c7422980a3b75e3213febfb811ffd6df76e68` завершился успешно
22 октября 2026 года с первой попытки.

- Все 233 Python-теста прошли на GitHub runner без пропусков.
- Повторно проверены pins, 40 применимых патчей Vanadium и интеграция
  доработок Argon с закреплённым Chromium; playback flow и C++ DNS/IP
  constraints с новым BoringSSL прошли.
- Полный checkout подготовлен с применением выбранных патчей и dependency hooks.
- Полный GN-граф ARM64: 79 650 targets из 5010 файлов; ARMv7: 66 470
  targets из 5007 файлов. В обоих графах Ninja подтвердил все три явные цели
  основного `build.sh`: JNI-объект `argon_certificate_domains_settings.o`,
  `chrome_java` и `chrome_public_apk`.
- Нативный `argon_domain_policy_tests` собран из новой базы: все 19 тестов
  `TitaniumRuDomainPolicyTest` и `ArgonRussianCaPolicyTest` прошли с настоящими
  GURL, ICU, public/private PSL и preferences.
- В полных Android GN-графах предупреждений о неприменяемых аргументах нет.
  Урезанный host-граф не использует `blink_symbol_level`: Blink в этот target
  не входит. Это предупреждение не относится к Android-конфигурациям.

Локально повторно прошли Python suite, обе preflight/config проверки, shell
syntax, прямой upstream integration, реальный AndroidX playback flow и заново
собранный C++ constraints test. Единственный локальный пропуск связан с
отсутствием `/dev/fd`; на GitHub тот же тест прошёл.

Снимок образа и Actions caches относится к моменту проверки 22 октября 2026 года.
Тесты кеша проверяют поведение восстановления, снимков, очистки и продолжения;
реальный ccache новой Android-сборки 156 ещё не прогревался. Холодная validation
не публикует image: первый ручной цикл после слияния самостоятельно обновит
`branch-main` и начнёт накапливать кеши 156.

Результаты привязаны к указанному code commit. Последующий коммит меняет только
документацию; проверенный код конвейера и приложения остаётся тем же.
В `main` изменения не слиты.

## Границы подтверждения

Локально выполнены preflight обеих архитектур, Python suite, интеграция патчей
с закреплённым Chromium, host playback flow и C++ constraints с новым BoringSSL.
Один Python-тест, требующий `/dev/fd`, пропущен ограниченной локальной средой;
GitHub runner запускает его в обычном Linux-окружении.

Полный APK-конвейер в текущей конфигурации разрешён только из `main`;
в этой ветке сборка APK не запускалась.

Полная подготовка checkout, полные GN-графы обеих ABI и production-тесты
GURL/ICU/PSL подтверждены указанным прогоном GitHub Actions. Host-сценарии
не подтверждают компиляцию Android JNI/Java, установку APK, реальные
TLS-соединения и поведение на устройстве. Перед релизом
нужны APK для обеих ABI и Android smoke tests, включая расширения, настройки
сертификатов, фоновое воспроизведение и оба окна очистки данных.
