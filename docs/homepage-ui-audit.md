# Проверка логики домашней страницы

База проверки: `main`, `4a06ae6cef49397655bf71c28d2dbc61d632b90d`.
Сценарии воспроизведены на production HTML/JS в Chromium, с тестовыми ярлыками.
Правки ниже пока не внесены: это результаты для обсуждения.

| Сценарий | Что происходит | Предлагаемое поведение |
| --- | --- | --- |
| Открыть папку → ярлык → Переместить → Отмена переноса | Данные сохраняются, но кнопка «Изменить папку» исчезает до повторного открытия папки | Восстанавливать все действия обычного режима редактирования |
| Открыть папку → ярлык → Изменить → Отмена или Сохранить | Диалог папки тоже закрывается; пользователь возвращается к корневому избранному | Возвращать пользователя в исходную папку |
| Перемещать ярлык между папками через «Переместить» | Внутри папки доступны только «В избранное» и отмена. Другая папка недоступна за модальным окном | Показывать выбор папки назначения. Сейчас прямой путь доступен через Изменить → Расположение |
| Переместить саму папку | Подсказка обещает «На папку — перенести внутрь», но папки не вкладываются: меняется порядок в корне | Подсказка должна учитывать тип перемещаемого элемента |
| Добавить в избранное → Папка | В поле названия остаётся подсказка «Название сайта» | Показывать «Название папки» |
| Добавить свой поисковик | На странице есть выбор и добавление, но нет удаления или изменения созданной записи | Предусмотреть управление своими поисковиками |

Отдельно подтверждена ранее найденная лишняя кнопка «Готово» при обычном
просмотре папки: она дублирует закрытие крестиком.

## Проверенные переносы

- Из корневого избранного в папку через Переместить → нажатие на папку.
- Из папки в избранное через Переместить → В избранное.
- Между папками через Изменить → Расположение.
- Отмена переноса внутри папки.

Во всех этих сценариях сохранены ID ярлыка, название, полный URL с параметрами
и своя встроенная иконка. Дублирования и потери ярлыка не обнаружено.
Проверка не заменяет испытание жестов на Android-устройстве.

## Ручной размер

В рабочей ветке добавлен третий вариант «Вручную», ввод 50–200%, предпросмотр,
проверка диапазона, сохранение последнего ручного значения, резервная копия
и восстановление. Проверены узкий экран 320 px, папки, перезапуск страницы,
старые копии и чтение новой копии точным кодом прежнего main.

ввода процента; он ещё не исправлен в черновике.

## Дополнительная проверка поиска, форм и восстановления

Проверен коммит PR #82 `624f4717bf0297922c7f6ccf0f64ada229f7049e`.
Все сценарии ниже повторены в Chromium 141 на production HTML/JS, при ширине
360 px и с тестовыми данными. Проверки не меняли пользовательские профили.
Ошибки не исправлялись в рамках этого аудита.

### Воспроизводимые ошибки

| Приоритет | Сценарий | Фактический результат | Требуемое поведение |
| --- | --- | --- | --- |
| Высокий | В первой вкладке изменить название ярлыка без сохранения; во второй поменять тему страницы | Форма в первой вкладке закрывается, редактирование выключается, черновик исчезает. В сохранённых данных остаётся прежнее название | Применять независимые настройки без закрытия формы и потери введённого текста |
| Высокий | При изменении ярлыка выбрать повреждённый файл broken.png с MIME image/png, затем сохранить | Показывается значок-заглушка, но файл принимается. Предыдущая своя иконка заменяется некорректными данными; появляется «Изменения сохранены» | Проверять декодирование изображения до замены и оставлять прежнюю иконку при ошибке |
| Высокий | При повреждённом JSON настроек открыть Перенос данных → Сохранить копию | Обычный экспорт выдаёт корректный JSON с нулём ярлыков и настройками по умолчанию, сообщая об успехе | Не выдавать пустое состояние за копию повреждённых исходных данных; предусмотреть явный экспорт исходных данных для восстановления или объяснить недоступность обычного экспорта |
| Средний | Добавить ярлык с адресом example.com:8443/path | Появляется «Укажите корректный адрес сайта». Тот же адрес с https:// сохраняется, а поле поиска HTML-страницы принимает адрес без схемы и открывает https://example.com:8443/path | Одинаково распознавать hostname:port в полях адреса; не считать hostname схемой URL |
| Средний, новая доработка PR #82 | Выбрать Вручную, ввести 175 и сразу нажать «Готово» | Процент сохраняется, но окно остаётся открытым. Второе нажатие закрывает окно. Если предварительно нажать Enter, первое нажатие «Готово» работает | Автосохранение при выходе из поля должно сохранять исходное действие пользователя и закрывать настройки одним нажатием |

В случае повреждения настроек исходная строка в localStorage остаётся
нетронутой: проблема состоит в содержимом и сообщении обычного экспорта,
а не в удалении исходной строки. В случае черновика также не исчезает ранее
сохранённый ярлык — теряется именно несохранённый ввод.

### Причины, подтверждённые кодом

- `syncStoredState()` закрывает любой модальный диалог и вызывает
  `setEditing(false)` при событии storage, включая независимую смену темы.
- Загрузка своей иконки проверяет MIME/размер и читает файл через FileReader,
  но не проверяет декодирование изображения перед сохранением.
- После ошибки чтения HomepageStore оставляет начальное состояние в памяти;
  `exportBackup()` экспортирует это состояние без проверки loadError.
- `normalizedUrl()` принимает часть до двоеточия за схему, включая hostname
  перед портом. `navigationTarget()` использует другое распознавание адреса.
- В ручном режиме обработчик change запускает `writeState()`, который временно
  делает весь body inert; исходное нажатие на кнопку не завершается.

Синхронизация черновика, нормализация адресов и обычный экспорт совпадают
с кодом main `4a06ae6cef49397655bf71c28d2dbc61d632b90d`. Загрузка своей
иконки также не изменялась в PR #82. Ошибка ручного процента относится
к новой доработке, а не к уже выпущенному поведению страницы.

### Наблюдения, требующие UX-решения

- Один и тот же URL своего поисковика можно добавить многократно: создаются
  разные записи без предупреждения о дубликате. Это усугубляет ранее найденное
  отсутствие удаления и изменения таких записей на странице.
- Нажатие вне формы с изменённым названием сразу закрывает её и теряет
  несохранённый текст. Стоит определить единое поведение для закрытия
  заполненных форм. Отдельной ошибкой сохранённых данных это не считается.

## Фон страницы — промежуточный этап

Подготовлены обработка метаданных Bing, загрузка выбранной фотографии через
существующий ограниченный транспорт WebUI, подготовка изображения и формат
хранения фона в резервной копии. Добавлены проверки данных, авторства,
адресов Bing и совместимости формата. Новый модуль включён в ресурсы APK.

Ещё не завершены экран выбора своего фона/Bing в настройках, применение фона
на странице, кнопка скачивания и полный UI-сценарий восстановления фона.
Черновик PR не следует считать готовой реализацией этой части.
