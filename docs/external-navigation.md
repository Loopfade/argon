# Открытие ссылок в приложениях

В **Настройки → Конфиденциальность и безопасность → Безопасность → Открытие ссылок в приложениях** доступны три режима. По умолчанию выбран **Разрешать**, сохраняющий стандартные проверки Chromium, включая необходимость жеста пользователя, ограничения фоновых вкладок и предупреждения при выходе из инкогнито. Режим **Только для сайтов из списка** разрешает передачу ссылки приложению только для её веб-адреса назначения. Режим **Запрещать** запрещает передачу ссылок приложениям независимо от списка.

Пункт находится поиском настроек по названию, а также по словам «ссылки», «приложения» и «внешние приложения». Результат открывает тот же экран управления режимом и списком сайтов.

Список изначально пуст. Пользователь добавляет домен или вставляет HTTP(S)-ссылку. Перед сохранением редактор показывает канонический домен; путь, параметры и фрагмент в правило не входят. Правило охватывает домен и его поддомены по границам DNS-меток: `example.com` разрешает `m.example.com`, но не `notexample.com` и не `example.com.evil.test`. Введённый поддомен не расширяется до родительского сайта: `m.example.com` не разрешает `example.com`. Международные домены хранятся в канонической форме GURL. DNS root dot не создаёт отдельного правила.

IP-адреса, одиночные имена, доменные суффиксы общего и частного пользования (`co.uk`, `github.io`), адреса с логином и паролем и шаблоны с `*` не принимаются. Список ограничен 100 сайтами. Для удаления нужно подтвердить конкретный домен. Режим и список сохраняются в закрытых настройках приложения; страницы сайтов не могут их изменять. Смена режима не очищает список. Изменения применяются при следующей проверке ссылки во всех вкладках. Повреждённый режим или список не добавляет разрешений.

## Обработка перехода

Дополнительная проверка в `ExternalNavigationHandler.shouldOverrideUrlLoading()` выполняется после разбора Intent и валидации HTTP(S) fallback, до стандартного механизма разрешения и запуска приложений. Она использует отдельный метод делегата, поэтому ограничение действует и в Custom Tabs, где Chromium переопределяет обычный `shouldDisableExternalIntentRequestsForUrl()`.

- HTTP(S)-ссылка, которой запрещён запуск приложения, остаётся обычной навигацией браузера.
- Для `intent://` разрешение проверяется по фактическим данным Intent, только если это HTTP(S)-адрес. Отображаемый host обёртки, referrer, origin исходной страницы и `browser_fallback_url` не дают разрешения на запуск.
- Каждый HTTP(S)-адрес после перенаправления проверяется заново. Разрешение предыдущего адреса не переносится на следующий сайт.
- Запрещённый Intent с валидным HTTP(S) fallback открывает fallback в браузере напрямую. Ветки запуска WebAPK и магазина приложений при этом не вызываются.
- Даже у разрешённого Intent запасной адрес проверяется отдельно перед запуском WebAPK или магазина. Установка отсутствующего приложения проверяется по адресу `play.google.com`; если этот сайт не разрешён, страница магазина открывается в браузере.
- Если явного fallback нет, HTTP(S)-данные Intent используются как веб-версия ссылки.
- Запрещённая ссылка без веб-адреса и fallback (`tg://`, `tel:`, `mailto:` и подобные) поглощается обработчиком. Текущая страница сохраняется, показывается краткое сообщение. Асинхронный callback завершается через очередь UI после возврата результата перехвата.
- `chrome://`, локальные документы и другие внутренние схемы браузера сохраняют штатную обработку. Явная команда браузера «Открыть в приложении», где она доступна, остаётся отдельным действием пользователя.

В разрешающем режиме дополнительная проверка не меняет поведение Chromium. В режиме списка она не отменяет штатные ограничения Chromium: наличие сайта в списке не гарантирует открытие приложения при отсутствии обработчика или разрешённого пользовательского действия. Общая политика действует также в инкогнито, без записи посещённых адресов в список, и в Custom Tabs Argon. Она не управляет ссылками, которые Android передал другому приложению до запуска браузера, и не управляет WebView других приложений.

## Проверки

`python3 -m unittest discover -s tests -p test_external_navigation.py -v` компилирует production Java-классы политики и экрана настроек с адаптерами платформенных служб. Проверяются три режима, домены и поддомены, IDN, границы DNS-меток, сохранение и перезапуск, некорректные настройки, пустой список и лимит, редактор и отмена ввода, удаление с подтверждением, независимая проверка перенаправлений, Intent/fallback и завершение перехвата.

`tests/check_upstream_patches.py` применяет патч дважды к закреплённому Chromium, проверяет положение перехвата до запуска приложений, API асинхронного callback и наследование политики Custom Tabs, а затем исполняет извлечённый production-перехват. Каталоги Java и ресурсов входят в общую проверку. CI дополнительно проверяет графы Android и компилирует `chrome_java`. Эти проверки не заменяют проверку APK на устройстве с установленными приложениями и Android App Links.
