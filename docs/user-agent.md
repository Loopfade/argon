# User-Agent: поведение и проверка

Настройка выбирает семейство строки User-Agent. Режим отображения страницы и исключения сайтов принадлежат штатной настройке Chromium «Версия для ПК».

## Правила применения

| Действие | До перезапуска | После перезапуска |
| --- | --- | --- |
| Выбрать Firefox или Яндекс | Прежнее семейство во всех вкладках и фоновых обработчиках | Выбранное семейство |
| Сохранить собственную строку | Прежняя строка, виден статус ожидания | Новая строка в обоих режимах |
| Выбрать «По умолчанию (Chrome)» | Прежний вариант | Штатный UA и метаданные Chromium/Vanadium |
| Нажать «Позже» | Выбор сохранён, доступна кнопка применения | Выбор применится при следующем запуске процесса браузера |
| Нажать «Отменить изменение» | Сохранённый выбор возвращается к действующему | Изменения нет |
| Переключить «Версия для ПК» | Применяется сразу для сайта, с действующим семейством UA | Сохранённое правило сайта остаётся |
| Повторно выбрать действующий вариант | Ничего не перезагружается | Изменения нет |

У собственной строки мобильный и настольный варианты совпадают; кнопка «Версия для ПК» продолжает менять режим отображения. Пока ожидается смена семейства, эта кнопка использует действующее семейство.

Миграция `CHROME_MOBILE`/`CHROME_DESKTOP` → `DEFAULT`, `FIREFOX_*` → `FIREFOX`, `YANDEX_*` → `YANDEX` не пишет настройки сайтов. Некорректный сохранённый custom UA и неизвестное имя пресета дают штатный режим. Браузер не пытается восстановить исключения, которые старая версия уже перезаписала: их прежние значения не сохранены.

## Реализация

- `ArgonUserAgent.applySavedOverride()` фиксирует выбор один раз при старте процесса. Сохранение предпочтений не меняет командную строку или уже созданные объекты Chromium. Новые вкладки, процессы отображения, Service Worker и сетевые контексты в этом запуске получают то же действующее семейство.
- Кнопка перезапуска завершает запись SharedPreferences и вызывает штатный `ApplicationLifetime.terminate(true)`. Chromium сохраняет состояние сеанса и перезапускает процесс через `BrowserRestartActivity`. При ошибке записи перезапуск не выполняется, показано сообщение; несохранённый текст страниц не гарантируется к восстановлению.
- Смена семейства не обращается к `REQUEST_DESKTOP_SITE`, не пишет правила доменов и не инициирует перезагрузку открытых вкладок. Удалено общее ожидание ответов renderer-процессов.
- Штатный режим не задаёт Argon override, поэтому UA, Client Hints и настольный вариант остаются штатными. Для совместимых строк и custom UA не отправляются `Sec-CH-UA*`: проверяются и навигация в browser-процессе, и подресурсы в renderer. Флаг подавления передаётся новым renderer-процессам. Остальные Client Hints этим флагом не отключаются.
- JavaScript API `navigator.userAgentData` в режиме подмены не эмулирует API Firefox или Яндекса: метаданные очищены, но само API Chromium может быть доступно. `navigator.platform`, графический стек и возможности движка не маскируются.

## Автоматические проверки

- Production-модель Java: все старые имена пресетов, штатный режим без override, ASCII/CRLF/длина, сохранённое и действующее значения, отмена, неизменность процесса и сохранение выбора между двумя отдельными JVM.
- Production-экран настроек с Android-адаптерами и настоящими строками RU/EN: открытие списка, отмена выбора и ввода, неправильная строка, отложенное применение, повторное открытие настроек, обновление при возврате, отмена ожидающего изменения, перезапуск и ошибка сохранения.
- C++: компиляция production-парсера override и вставленных условий для UA Client Hints; штатные метаданные сохраняются, подмена подавляет hints для навигации и подресурсов.
- Полная проверка патчей на закреплённом Chromium: применение дважды, исходные API, XML, каталог Java и локализация. Старая подготовленная версия с live-UA кодом отклоняется и требует чистого checkout.
- Android CI компилирует изменённые native-объекты и `chrome_java` на закреплённой сборочной цепочке.

Host-тесты с адаптерами не заменяют запуск APK и перехват HTTP-запросов.

## Проверка APK перед выпуском

Использовать тестовый HTTPS-сайт, который показывает заголовки навигации и `fetch`, поддерживает Service Worker и выводит `navigator.userAgent`/`navigator.userAgentData`. Проверять настоящий запрос на сервере, учитывая кеш и возможность ответа из Service Worker.

1. На чистой установке проверить мобильный и настольный UA и штатные Client Hints. Сохранить настольное исключение для двух сайтов; один оставить открытым, второй закрыть.
2. Запустить Service Worker и выбрать Firefox. Нажать «Позже»: действующий UA не должен меняться в открытой странице, новой вкладке, запросах worker, подресурсах и инкогнито. Ни одна страница не должна автоматически перезагрузиться.
3. Переключить «Версия для ПК» до перезапуска: строка должна стать настольной для прежнего семейства.
4. Перезапустить через настройки. Проверить выбранное семейство для навигации, редиректа, подресурса и нового запроса Service Worker, включая другой renderer-процесс. Заголовков `Sec-CH-UA*` при подмене быть не должно. Оба сохранённых исключения сайтов должны остаться.
5. Переключить «Версия для ПК» после перезапуска: мобильный/настольный Firefox меняется сразу. Повторить с Яндексом. Для custom UA проверить неизменность строки при смене режима отображения.
6. Проверить «Отменить изменение», отмену редактора, пустую/слишком длинную/не-ASCII строку, возврат из другой Activity настроек, повторный выбор текущего варианта и повторное открытие после «Позже».
7. Вернуться к штатному режиму, перезапустить и проверить восстановление UA Client Hints. Повторить после обновления сборки с каждым старым мобильным/настольным пресетом.
8. Проверить перезапуск с несколькими окнами, фоновым аудио, инкогнито и зависшим renderer-процессом. Отказ перезапуска по политике явного выхода не должен обходить ограничения очистки. Подтвердить сценарии на ARM64/ARMv7 и поддерживаемых версиях Android.
