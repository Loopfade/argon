# User-Agent: поведение и проверка

Настройка выбирает семейство строки User-Agent. Режим отображения страницы и исключения сайтов принадлежат штатной настройке Chromium «Версия для ПК».

В списке настроек показано название действующего варианта. Пояснение находится в прокручиваемом окне выбора под четырьмя вариантами, а ожидающее применения изменение по-прежнему отмечено отдельно.

Firefox и Яндекс — готовые строки для совместимости, а не определение установленного браузера или устройства. Их версии, ОС и модель заданы в пресетах; строка действительно передаётся сайтам. Движок остаётся Chromium. Смена строки не скрывает `navigator.platform`, `navigator.vendor` и остальные возможности браузера.

## Правила применения

| Действие | До перезапуска | После перезапуска |
| --- | --- | --- |
| Выбрать Firefox или Яндекс | Прежнее семейство во всех вкладках и фоновых обработчиках | Выбранное семейство |
| Сохранить собственную строку | Прежняя строка, виден статус ожидания | Новая строка в обоих режимах |
| Выбрать «По умолчанию (Chrome)» | Прежний вариант | Штатный UA и метаданные Chromium/Vanadium |
| Нажать «Позже» | Выбор сохранён, доступна кнопка применения | Выбор применится при следующем запуске процесса браузера |
| Нажать «Отменить изменение» | Сохранённый выбор возвращается к действующему | Изменения нет |
| Переключить «Версия для ПК» | Применяется сразу для сайта, с действующим семейством UA | Сохранённое правило сайта остаётся |
| Повторно выбрать действующий вариант | Ничего не перезагружается | Изменения нет |

У собственной строки мобильный и настольный варианты совпадают; кнопка «Версия для ПК» продолжает менять режим отображения. Пока ожидается смена семейства, эта кнопка использует действующее семейство.

При завершении переключения «Версия для ПК» страница заново рассчитывает начальный масштаб для выбранного режима и возвращается к начальной позиции прокрутки. Масштаб не фиксируется на 100%: учитываются viewport и ширина содержимого конкретной страницы. Обычное обновление и переходы «Назад/Вперёд» сохраняют пользовательское увеличение.

Возврат мобильного режима не гарантирует мобильную версию каждого сайта. Сайт может иметь фиксированную ширину, собственный переключатель версии или сохранённое предпочтение в cookie. Если своя строка UA описывает настольный браузер, сервер продолжает получать её и после снятия галочки.

Миграция `CHROME_MOBILE`/`CHROME_DESKTOP` → `DEFAULT`, `FIREFOX_*` → `FIREFOX`, `YANDEX_*` → `YANDEX` не пишет настройки сайтов. Некорректный сохранённый custom UA и неизвестное имя пресета дают штатный режим. Браузер не пытается восстановить исключения, которые старая версия уже перезаписала: их прежние значения не сохранены.

## Реализация

- `ArgonUserAgent.applySavedOverride()` фиксирует выбор один раз при старте процесса. Сохранение предпочтений не меняет командную строку или уже созданные объекты Chromium. Новые вкладки, процессы отображения, Service Worker и сетевые контексты в этом запуске получают то же действующее семейство.
- Кнопка перезапуска завершает запись SharedPreferences и вызывает штатный `ApplicationLifetime.terminate(true)`. Chromium сохраняет состояние сеанса и перезапускает процесс через `BrowserRestartActivity`. При ошибке записи перезапуск не выполняется, показано сообщение; несохранённый текст страниц не гарантируется к восстановлению.
- Смена семейства не обращается к `REQUEST_DESKTOP_SITE`, не пишет правила доменов и не инициирует перезагрузку открытых вкладок. Удалено общее ожидание ответов renderer-процессов.
- Штатный режим не задаёт Argon override, поэтому UA, Client Hints и настольный вариант остаются штатными. Для совместимых строк и custom UA не отправляются `Sec-CH-UA*`: проверяются и навигация в browser-процессе, и подресурсы в renderer. Флаг подавления передаётся новым renderer-процессам. Остальные Client Hints этим флагом не отключаются.
- JavaScript API `navigator.userAgentData` в режиме подмены не эмулирует API Firefox или Яндекса: метаданные очищены, но само API Chromium может быть доступно. `navigator.platform`, графический стек и возможности движка не маскируются.
- При ручном выборе «Версия для ПК» `TabUtils` сначала обновляет UA override существующего `WebContents` и флаг наследования режима новыми вкладками, затем меняет флаг навигации и при необходимости обновляет документ. Любой явный выбор записывается как `TabUserAgent.MOBILE` или `TabUserAgent.DESKTOP` текущей вкладки, даже если он совпадает с правилом сайта, и восстанавливается вместе с вкладкой. Настройка `REQUEST_DESKTOP_SITE` при этом не переписывается. Автоматические изменения режима не заменяют ручной выбор. `TabImpl.calculateUserAgentOverrideOption()` учитывает режим вкладки на следующих загрузках; `RequestDesktopSiteWebContentsObserverAndroid` не возвращает режим сайта для renderer-initiated navigation, пока у вкладки есть ручной override. Вкладки без override по-прежнему следуют правилам Chromium.
- Второй аргумент `ContentUtils.setUserAgentOverride(webContents, overrideInNewTabs)` задаёт наследование UA новыми вкладками, **а не** выбор мобильной или настольной строки. `NavigationController` выбирает режим навигации. В Chromium 158 `WebContentsImpl::SetUserAgentOverride()` дополнен синхронизацией флага новых вкладок и отложенных загрузок даже при неизменной строке UA (например, при custom UA).
- Переключение «Версия для ПК» различает флаг запрошенного режима в `NavigationEntry` и режим загруженного документа в `PageImpl`. После отменённой перезагрузки или установки флага без перезагрузки повторный запрос режима запускает загрузку, если документ ещё использует другой UA. Совпадения одного флага недостаточно для пропуска операции. Пока новая загрузка не завершилась, прежний документ может продолжать использовать прежний UA. Также проверяется незавершённая навигация: если она собирается загрузить противоположный режим, выбранный режим не считается применённым, даже когда текущий документ и сохранённый флаг совпадают. Такая навигация заменяется перезагрузкой с выбранным UA.
- Если переключение пришлось отложить из-за выполняющейся навигации, новый выбор отменяет устаревшую отложенную задачу. Проверка необходимости перезагрузки выполняется при применении последнего выбора. Защита начальной записи навигации, сохранение исключений сайтов и штатный выбор исходного URL для перезагрузки сохранены.
- Для reload и замены текущей записи renderer сравнивает действующий режим старого документа с режимом нового. Одноразовый флаг в `DocumentState` сбрасывает скопированное состояние viewport через `ResetScrollAndScaleState()` после установки нового `HistoryItem`, до восстановления масштаба из истории. Это устраняет перенос масштаба ПК в мобильную страницу, когда старое значение укладывается в её допустимые пределы. До завершения загрузки старый документ не сбрасывается; флаг не копируется при замене документа через javascript:, XSLT или discard. Формы сохраняют штатное подтверждение повторной отправки.

## Автоматические проверки

- Production-модель Java: все старые имена пресетов, штатный режим без override, ASCII/CRLF/длина, сохранённое и действующее значения, отмена, неизменность процесса и сохранение выбора между двумя отдельными JVM.
- Production-экран настроек с Android-адаптерами и настоящими строками RU/EN: открытие списка, отмена выбора и ввода, неправильная строка, отложенное применение, повторное открытие настроек, обновление при возврате, отмена ожидающего изменения, перезапуск и ошибка сохранения.
- C++: компиляция production-парсера override и вставленных условий для UA Client Hints; штатные метаданные сохраняются, подмена подавляет hints для навигации и подресурсов.
- C++ навигация: извлечённые функции Chromium с адаптерами JNI, очереди задач и загрузки. Проверяются полные циклы мобильный → ПК → мобильный, отмена загрузки и повтор в обе стороны, установка режима без перезагрузки, исходный URL/POST, быстрый повторный выбор, незавершённая навигация с противоположным или совпадающим UA и защита начальной записи. Регрессии сначала воспроизводятся на непатченых функциях. Проверка закреплённых исходников сравнивает извлечённые функции с тестовыми файлами и выполняет те же сценарии на применённом патче.
- Java/C++ логика вкладки: проверяются синхронизация UA override до reload, отдельность ручного и автоматического выбора, приоритет табового режима при загрузке и блокировка перезаписи из RDS observer. Изменения сверяются с исходниками закреплённого Chromium и применяются повторно без дублирования.
- C++ масштаб: настоящие функции сброса, восстановления viewport, расчёта начального масштаба и клонирования состояния документа с адаптерами layout/compositor. Девять сценариев проверяют смену режима в обе стороны, замену записи после перенаправления, обычное и принудительное обновление, историю, отмену, подфрейм, удалённый главный фрейм и одноразовое потребление флага. Вариант без исправления воспроизводит сохранение старого масштаба. CI также проверяет порядок вызовов в закреплённом Chromium и компилирует `render_frame_impl`/`document_state`.
- Полная проверка патчей на закреплённом Chromium: применение дважды, исходные API, XML, каталог Java и локализация. Старая подготовленная версия с live-UA кодом отклоняется и требует чистого checkout.
- Android CI компилирует изменённые native-объекты и `chrome_java` на закреплённой сборочной цепочке.

Host-тесты с адаптерами не заменяют запуск APK и перехват HTTP-запросов.

## Проверка APK перед выпуском

Использовать тестовый HTTPS-сайт, который показывает заголовки навигации и `fetch`, поддерживает Service Worker и выводит `navigator.userAgent`/`navigator.userAgentData`. Проверять настоящий запрос на сервере, учитывая кеш и возможность ответа из Service Worker.

1. На чистой установке проверить мобильный и настольный UA и штатные Client Hints. Сохранить настольное исключение для двух сайтов; один оставить открытым, второй закрыть.
2. Запустить Service Worker и выбрать Firefox. Нажать «Позже»: действующий UA не должен меняться в открытой странице, новой вкладке, запросах worker, подресурсах и инкогнито. Ни одна страница не должна автоматически перезагрузиться.
3. Переключить «Версия для ПК» до перезапуска: строка должна стать настольной для прежнего семейства.
4. Перезапустить через настройки. Проверить выбранное семейство для навигации, редиректа, подресурса и нового запроса Service Worker, включая другой renderer-процесс. Заголовков `Sec-CH-UA*` при подмене быть не должно. Оба сохранённых исключения сайтов должны остаться.
5. Несколько раз включить и выключить «Версия для ПК» после перезапуска. Особое внимание уделить 4PDA: проверить смену сетевого `User-Agent`, запуск реальной навигации, смену viewport и сохранение режима при внутренних переходах сайта. Сравнить ручной режим вкладки с глобальными правилами RDS и проверить, что другая вкладка не наследует её исключение. После каждой завершённой загрузки проверить мобильный/настольный Firefox в документе, новом `fetch` и JavaScript. Повторить с Яндексом и штатным режимом, в том числе после отмены перезагрузки и при быстрых повторных нажатиях. Для custom UA проверить неизменность строки при смене режима отображения.
6. Проверить «Отменить изменение», отмену редактора, пустую/слишком длинную/не-ASCII строку, возврат из другой Activity настроек, повторный выбор текущего варианта и повторное открытие после «Позже».
7. Вернуться к штатному режиму, перезапустить и проверить восстановление UA Client Hints. Повторить после обновления сборки с каждым старым мобильным/настольным пресетом.
8. Проверить перезапуск с несколькими окнами, фоновым аудио, инкогнито и зависшим renderer-процессом. Отказ перезапуска по политике явного выхода не должен обходить ограничения очистки. Подтвердить сценарии на ARM64/ARMv7 и поддерживаемых версиях Android.
9. Проверить возврат масштаба после режима ПК на странице с `width=device-width`, с неуказанным `initial-scale`, без meta viewport и с перенаправлением на мобильный домен. Перед каждым переключением изменить масштаб жестом. После завершения загрузки должен выбираться начальный масштаб текущей страницы. Отдельно проверить сохранение ручного увеличения при обычном обновлении и «Назад/Вперёд», отмену переключения, формы с подтверждением повторной отправки и сайт с собственной настройкой настольной версии. Страница без мобильной раскладки может оставаться широкой.
