# Период удаления данных

Быстрая очистка и полный экран удаления данных используют существующую
настройку периода в текущем профиле Chromium. Выбор в одном окне доступен
при следующем открытии другого, в том числе при переходе через дополнительные
настройки. В новом профиле оба окна начинают с последнего часа.

Период сохраняется сразу при выборе. «Отмена» отменяет удаление данных,
но сохраняет выбранный период. Выбор периода сам по себе не удаляет данные
и не сохраняет изменения флажков типов данных. Их подтверждение остаётся
в существующей логике Chromium.

Новая настройка или миграция профиля не добавляются. Уже сохранённый период
используется при первом открытии быстрого окна. Неподдерживаемое значение
обрабатывается так же, как на полном экране: выбирается последний час.

## Применение и обновление Chromium

`scripts/apply_browsing_data_period.py` вызывается из `patch.sh` после загрузки
исходников и toolchain, вместе с остальными локальными патчами. Скрипт подготовки
тяжёлого source-слоя Docker не меняется, поэтому этот слой можно переиспользовать.
Патч меняет только инициализацию списка в `QuickDeleteDialogDelegate`, обработку
выбора в `QuickDeleteMediator` и обработку периода в `ClearBrowsingDataFragment`.
Диапазоны и названия периодов, типы удаляемых данных и обработчики подтверждения
удаления остаются в Chromium.

Перед записью файлов проверяются SHA-256 полных исходных методов. Повторное
применение допускает только точные вставки Argon. Изменение метода, повреждённый
патч или новый способ чтения периода на полном экране останавливают подготовку
до изменения любого файла.

При обновлении базы необходимо пересмотреть патч и закреплённые фрагменты
в `tests/fixtures/browsing_data_period.json`. Если Chromium реализует нужное
общее поведение, собственную поправку следует удалить. Успешное текстовое
применение само по себе не заменяет проверку поведения.

## Проверки

`python3 -m unittest discover -s tests -p test_browsing_data_period.py -v`
проверяет повторное применение, отказ при изменении базы и Java-сценарии всех
предлагаемых периодов, обоих окон, отмены, перехода, повторного использования
спиннера, восстановления сохранённого профиля и разделения профилей.
Неизменённые методы Chromium воспроизводят исходную проблему в том же сценарии.

`python3 tests/check_upstream_patches.py` применяет поправку к полным файлам
закреплённого Chromium после соответствующих патчей Vanadium. Проверка сверяет
JNI-доступ к существующей настройке, зависимость Java-модуля, компилирует
и запускает те же сценарии с настоящими телами методов и повторяет применение
всего overlay. Host-адаптеры заменяют Android UI и запись нативных настроек;
это не проверка APK на устройстве.

Новый скрипт входит в отпечаток подготовленного Chromium image и входы релизного
APK. Образ со старым патчем не может быть переиспользован для новой реализации.
