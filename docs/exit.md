# Выход и очистка

Java-интеграция обращается к закрытому `TabImpl` через `ArgonExitTabHelper` в
пакете вкладок. Экран настроек использует обязательную property-анимацию
`SettingsFragment`. Проверка `tests/test_exit_android_api.py` компилирует целиком
production-классы моста и настроек, проверяет сохранение/закрытие обычных и
приватных вкладок и отказ при неподдерживаемой живой вкладке. В upstream-проверке
используется интерфейс настроек из закреплённого Chromium.

«Выход» в конце меню и подтверждённый `Ctrl+Q` запускают один сценарий:
остановка страниц, воспроизведения и загрузок, очистка выбранных данных,
закрытие всех окон и завершение основного процесса без перезапуска.
Фоновое воспроизведение не блокирует эту команду. Его сохранённый переключатель,
правила сайтов и лимиты не меняются.

Сворачивание, выключение экрана, пауза и истечение лимита воспроизведения
не запускают выход или очистку. Смахивание окна из списка недавних Android
не является командой «Выход» и не гарантирует очистку.

## Данные и вкладки

Настройки → Конфиденциальность и безопасность → «Очистка при выходе»:
история, cookies и данные сайтов, кэш, настройки сайтов, автозаполнение, пароли.
По умолчанию ничего не выбрано. Удаляются выбранные данные обычного профиля
за всё время, независимо от периода ручного удаления.

Закладки, расширения и их хранилища, настройки браузера, домашней страницы
`chrome://argon/` и фонового воспроизведения сохраняются. Скачанные файлы
не удаляются; текущие загрузки приостанавливаются.

Существующая настройка «Закрывать вкладки при выходе» определяет сохранение
обычной сессии. Если она выключена, навигационное состояние сохраняется,
но живые страницы уничтожаются до удаления данных. Если включена, вкладки
закрываются без Undo и без добавления этой сессии в недавно закрытые.
Сохранённые и общие группы скрываются, а не удаляются.
Приватные вкладки закрываются всегда. Восстановленная при следующем запуске
обычная сессия может создавать новые данные сайтов.

## Выполнение и сбои

Координатор всего процесса сохраняет снимок категорий и настройки вкладок.
Версионированный журнал записывается через `SharedPreferences.commit()` на
рабочем потоке; до подтверждения записи удаление не начинается. Повторные
команды не меняют снимок и не запускают вторую очистку.

Временно блокируется запуск renderer-процессов, включая фоновые workers.
Расширения переводятся в terminated без изменения сохранённых разрешений,
service workers останавливаются. Все модели вкладок, включая приватную и
архивированную, останавливают текущие загрузки. Закрываемые вкладки проходят
штатный путь TabRemover: наблюдатели получают уведомления, пока WebContents
ещё существует, затем содержимое уничтожается без поздних обработчиков `unload`.
Сохраняемые вкладки удерживают WebContents с навигацией на стороне браузера
до `saveState()`. До удаления данных ожидается завершение всех renderer-процессов.

Заблокированная навигация отменяется до создания speculative RenderFrameHost.
Обычная загрузка, внутренние страницы без URLLoader и страницы ошибок одинаково
освобождают NavigationRequest и сразу возвращают управление. Запрет нового
renderer не меняет успешный результат повторного Init уже работающего процесса.

После сброса записей localStorage штатный BrowsingDataRemover удаляет выбранные
категории. Маска web origins сохраняет внутреннее хранилище домашней страницы
и расширений. `failed_data_types` передаётся в Java. Штатный блокирующий
`saveState()` сохраняет сессию. Только после успешного удаления и записи
завершения журнала вызывается `ApplicationLifetime.terminate(false)`.
Все задачи удаляются из недавних; служебный перезапуск не отменяет выход.

Ошибка или таймаут не считаются успехом. Страницы остаются остановленными.
После ошибки доступен повтор; можно закрыть браузер с незавершённым журналом.
При таймауте параллельное удаление не запускается. Старые callback игнорируются.
Следующий запуск повторяет очистку по сохранённому снимку до загрузки страниц,
затем разрешает работу страниц и расширений. Восстановление очистки само по себе
не закрывает только что открытый браузер.

После явного выхода фоновые задания не загружают native и не возобновляют
загрузки до следующего видимого открытия. Это политика браузера, а не Android
force-stop: процессом и доставкой системных событий продолжает управлять ОС.

## Проверки

`apply_exit.py` выполняется после CA/JNI и фонового воспроизведения. Все входы
проверяются до записи; совместное повторное применение идемпотентно.
Наблюдатель профиля находится в основном слое браузера, без обратной зависимости
модуля профилей от UI. Модуль lifetime получает только общий предикат перезапуска.

Host-тесты компилируют и выполняют реальную Java-машину состояний для всех
64 сочетаний категорий, отложенную навигацию и production C++ защиту загрузок:
порядок этапов, восстановление, ошибки, повторы и старые callback. Обычный CI
проверяет закреплённые Chromium/Vanadium и наличие целей выхода, renderer guard
и Java в обоих Android-графах. Запросы Ninja выполняются через `-t query`.
До проверки графов `check-exit-dex.py` компилирует production `ArgonExitFlow`
закреплённым JDK и упаковывает его настоящим Chromium `dex.py`/CustomD8:
min API 29, incremental, intermediate и warnings-as-errors, как в обоих APK.
Контрольный `record` обязан воспроизвести запрет записей, а машина состояний и
неизменяемый `Selection` — создать DEX с обоими production-классами. Это
проверяет этап, которого нет у обычного запуска Java host-теста.
Полная Android-компиляция выполняется существующей ручной сборкой с сохраняемым
ccache; `argon_exit.o` добавлен в её обязательные цели. Эта сборка не запускается
обычной проверкой PR.

На устройстве проверяются несколько окон и инкогнито, музыка с выключенным экраном,
Play из уведомления, активная загрузка, сохранение домашней страницы, входящая
ссылка и поворот экрана во время очистки, прерывание процесса на каждом этапе
и оба значения настройки сохранения вкладок.

## Сверка с Bare, Vanadium и Chromium

Проверены [Bare 0118](https://github.com/BareBrowser/bare-browser/blob/a5a7ef74f3b77d45720b8c502cbacc30f2f3dbd5/patches/0118-Add-Exit-to-the-app-menu-and-let-it-clear-browsing-d.patch),
[Bare 0126](https://github.com/BareBrowser/bare-browser/blob/a5a7ef74f3b77d45720b8c502cbacc30f2f3dbd5/patches/0126-Clear-the-pending-flag-when-there-is-nothing-left-to.patch)
и закреплённый [Vanadium 0154](https://github.com/GrapheneOS/Vanadium/blob/2ae4335402eabcc6e025f3400185fe25094d8521/patches/0154-Toggle-for-closing-tabs-on-exit.patch).
API и инструменты сборки Argon сверяются с Chromium
`1d17a2e2ee147bb7d6ae2ab6abdb3a2510c17775`.

| Вопрос | Проверенное решение | Argon |
| --- | --- | --- |
| Категории и период | Bare использует битовую маску и BrowsingDataBridge с ALL_TIME | Те же шесть категорий, нулевая маска допустима, результат native-удаления сохраняется |
| Прерванная очистка | Bare хранит pending; 0126 исправляет его сброс при пустой выборке | Версионированный снимок категорий и вкладок; подтверждаются запись начала и завершение, восстановление не зависит от последующего изменения настроек |
| Несколько окон | Bare передаёт finishAndRemoveTask для текущего Activity | Остановка страниц всех моделей и ожидание renderer-процессов перед завершением приложения |
| Сохранение вкладок | Vanadium управляет восстановлением через shouldCloseTabsOnExit | Та же настройка; при выходе сохраняется навигация либо закрываются модели без Undo |
| Совместимость Java | Chromium запрещает records и AutoValue в Android-коде | Selection — static final class с final-полями и прежними аксессорами; явная проверка настоящим D8 |

В [сборке 40250577813](https://github.com/Loopfade/argon/actions/runs/40250577813)
`argon_exit.o` успешно скомпилировался на ARM64 и ARMv7; следующей ошибкой стал
запрещённый `record` при создании `chrome_java.dex.jar`. Успех javac и наличие
GN-целей не подтверждают DEX, линковку, упаковку и подпись. Эти этапы проверяет
полный artifacts-only workflow для обеих архитектур с проверкой ABI, ZIP,
zipalign, сертификата, подписи и метаданных APK.

Правило запрета records взято из
[Java style guide закреплённого Chromium](https://github.com/chromium/chromium/blob/1d17a2e2ee147bb7d6ae2ab6abdb3a2510c17775/styleguide/java/java.md).
Закладки, домашняя страница, дампы, категории удаления и ключи журнала при
замене Selection не меняются; его содержимое сохраняется как отдельные
примитивные значения, а не сериализованный Java-объект.
