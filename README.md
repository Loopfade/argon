# Argon

Argon — Android-браузер на базе [Titanium](https://github.com/jqssun/android-titanium-browser) и Chromium с поддержкой расширений и ограниченным доверием к встроенному российскому корневому УЦ.

> Ветка `experimental/ca-domain-allowlist` предназначена для тестирования пользовательского списка дополнительных доменов. Эта функция пока не входит в `main`.

## Реализовано

- Поддержка расширений Chromium, включая Manifest V2.
- Встроенный российский корневой УЦ с базовым ограничением доверия доменами `.ru`, `.рф` / `.xn--p1ai` и `.su`.
- Дополнительная проверка политики во встроенном верификаторе Chromium: доверие привязано к точному DER-корню, IP SAN запрещены, существующие ограничения не ослабляются.
- Пользовательский список дополнительных DNS-доменов в **Настройки → Конфиденциальность и безопасность → Сертификаты Argon**:
  - добавление и удаление записей;
  - хранение в Chromium PrefService;
  - нормализация регистра, завершающей точки и IDN;
  - запрет IP-адресов, wildcard-записей и публичных суффиксов вроде `.com`, `.net` и `.org`;
  - применение только к явно добавленному домену и его поддоменам.
- Цели сборки: `arm64-v8a`, `armeabi-v7a`, `x86_64` и `x86`.
- Автоматические проверки генератора патча и ограничений пользовательского списка доменов.

Argon пока сознательно сохраняет package ID `app.titaniumru.browser` для совместимости
с конфигурацией Titanium. APK Argon, подписанный отдельным ключом, нельзя установить
рядом с официальным Titanium или использовать для его обновления без удаления
предыдущей установки; это ограничение учитывается до принятия отдельного решения о
собственном package ID.

## Планируется

Перед переносом экспериментальной функции в основной релиз необходимо:

- выполнить полную сборку APK из этой ветки для поддерживаемых ABI;
- проверить на Android-устройстве или эмуляторе добавление, удаление и сохранение доменов;
- провести TLS smoke-тесты для встроенных зон, разрешённых пользовательских доменов и отрицательных сценариев;
- убедиться, что публичные суффиксы, wildcard-записи, IP-адреса и посторонние домены остаются запрещёнными;
- расширить интеграционные тесты Android UI и сетевого контекста;
- после успешной проверки отдельно принять решение о переносе изменений в `main`.

## Сборка и проверка

Сборка доступна [локально на Debian](BUILDING.md) или через **Actions → Build Argon → Run workflow**. Один запуск собирает одну архитектуру; по умолчанию это `arm64`. Режим `all` отключён. Для полной локальной подготовки требуется не менее 100 GiB свободного места.

GitHub-сборка использует один runner с подготовленным образом `ghcr.io/loopfade/argon-build`, закреплённым по digest. Изменения подготовленных исходников сначала требуют нового образа; последующее обновление digest в workflow запускает APK-сборку. Перед прогревом проверяются соответствие исходников образу и инструменты подписи. Tailscale и распределённые `sccache-dist` воркеры в текущем workflow не используются.

Результаты компиляции сохраняются через `ccache` и GitHub Actions Cache. Предусмотрено до 20 шагов по 20 минут, но шестичасовой лимит job имеет приоритет: прогрев останавливается раньше, резервируя примерно час на непрерывное завершение сборки и 30 минут на сохранение результатов. Линковка и другие операции вне `ccache` не переносятся между runner. Предыдущие архивы удаляются только после подтверждения нового архива через GitHub API. При исчерпании времени допускается до 10 автоматических продолжений той же архитектуры; ошибки компиляции и ранний код 137 не считаются штатным таймаутом.

Подробные сценарии проверки описаны в [VALIDATION.md](VALIDATION.md).
